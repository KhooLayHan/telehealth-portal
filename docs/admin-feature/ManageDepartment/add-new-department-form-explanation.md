# AddNewDepartmentForm.tsx Code Flow Explanation

## Short Version
`AddNewDepartmentForm` is an admin dialog component that collects a department name and optional description, validates input with Zod + TanStack Form, and submits to the generated API mutation `useAdminCreateDepartment`. On success, it shows a toast, invalidates the departments list query so the table refreshes, resets the form, and closes the dialog. The backend receives this at `POST /api/v1/admins/departments`, validates again with FluentValidation, creates the department entity, and returns a DTO used by the frontend flow.

## Technical Flow
1. Parent admin page controls whether the dialog is open via `open` and `onOpenChange` props.
2. User types `name` and optional `description`.
3. TanStack Form runs `addDepartmentSchema` on submit. Name must be present and <= 100 chars; description <= 500 chars.
4. If valid, `onSubmit` trims both fields and sends `{ name, description | null }` to `mutateAsync` from generated hook `useAdminCreateDepartment`.
5. Generated API client sends `POST /api/v1/admins/departments`.
6. Backend endpoint applies authorization policy + validation filter, then handler:
   - checks duplicate name (case-insensitive),
   - creates `Department` with slug,
   - saves to DB,
   - returns `AdminDepartmentDto`.
7. Frontend success handler shows success toast, invalidates departments list query (`getAdminGetAllDepartmentsQueryKey()`), and closes the modal.
8. Frontend error handler maps `ApiError` problem title to toast message.

## Frontend Code
From `frontend/src/features/admins/manageDepartments/AddNewDepartmentForm.tsx`:

```tsx
const addDepartmentSchema = z.object({
  name: z.string().trim().min(1, "Department name is required").max(100, ...),
  description: z.string().trim().max(500, ...),
});
```
This is client-side validation: fast feedback before API call.

```tsx
const { mutateAsync, isPending } = useAdminCreateDepartment({
  mutation: {
    onSuccess: async () => {
      await queryClient.invalidateQueries({ queryKey: getAdminGetAllDepartmentsQueryKey() });
      onOpenChange(false);
    },
    onError: (error) => { ... }
  }
});
```
This hook is generated by Orval. It wraps the backend endpoint and wires mutation lifecycle handlers.

```tsx
onSubmit: async ({ value }) => {
  const description = value.description.trim();
  await mutateAsync({
    data: {
      name: value.name.trim(),
      description: description.length > 0 ? description : null,
    },
  });
  form.reset();
}
```
The submitted payload is normalized (trim strings, empty description => `null`) before hitting backend.

From `frontend/src/api/generated/admins/admins.ts`:

```ts
export const getAdminCreateDepartmentUrl = () => `/api/v1/admins/departments`

export const adminCreateDepartment = async (adminCreateDepartmentCommand, options?) => {
  return ofetchMutator(getAdminCreateDepartmentUrl(), {
    method: 'POST',
    body: adminCreateDepartmentCommand,
    ...options
  })
}
```
This is the generated API function the mutation uses internally.

## Backend Code
From `backend/src/TeleHealth.Api/Features/Admins/CreateDepartment/AdminCreateDepartmentEndpoint.cs`:

```csharp
group.MapPost(ApiEndpoints.Admins.CreateDepartment,
    async (AdminCreateDepartmentCommand cmd, AdminCreateDepartmentHandler handler, CancellationToken ct) =>
    {
        var result = await handler.Handle(cmd, ct);
        return TypedResults.Created($"/api/v1/admins/departments/{result.Slug}", result);
    })
.RequireAuthorization(AuthConstants.AdminOrSuperAdmin)
.AddEndpointFilter<ValidationFilter<AdminCreateDepartmentCommand>>();
```
This wires route + auth + validation filter. The endpoint itself is thin and delegates business logic to handler.

## End-to-End Code Flow
1. Admin clicks “Add New Department” (dialog opens).
2. `AddNewDepartmentForm` renders controlled fields through TanStack Form.
3. User submits; Zod validation runs on submit.
4. Generated `useAdminCreateDepartment` sends POST request.
5. Backend endpoint receives `AdminCreateDepartmentCommand`.
6. `ValidationFilter` + `AdminCreateDepartmentValidator` enforce rules.
7. `AdminCreateDepartmentHandler` writes new record and returns DTO.
8. Frontend shows toast, invalidates departments query cache, and closes/reset form.

## Important Details
- Client and server both validate lengths and required name (defense in depth).
- The create endpoint is protected by `AuthConstants.AdminOrSuperAdmin`.
- Query invalidation is critical; without it, admin department list might show stale data.
- `description` is sent as `null` when empty, which avoids storing meaningless empty strings.
- Error branch uses `ApiError` title when available for better user feedback.

## Beginner Programmer Notes
- **TanStack Form** handles field state, touched status, submit lifecycle, and validation integration.
- **Generated hooks (Orval)** are typed wrappers around backend endpoints, so frontend avoids hand-written fetch code.
- **Mutation** means “write operation” (POST/PUT/DELETE) in TanStack Query terms.
- **Invalidate query** means “mark cached list stale and refetch,” so UI reflects latest backend data.
