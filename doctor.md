## Architecture Overview

```
Browser (React)
  └── Route file (TanStack Router)
        └── Feature Component  ←→  Hook (logic + state)
                                         └── Generated API Client (orval)
                                                └── Backend Endpoint (Minimal API)
                                                       └── Handler (business logic)
                                                              └── ApplicationDbContext (EF Core)
                                                                     └── PostgreSQL (Neon Dev / RDS Prod)
                                                                  [S3 for profile photo only]
```

**Tech stack:**
- **Frontend:** React + TypeScript, TanStack Router, TanStack Query, shadcn/ui, Framer Motion
- **Backend:** ASP.NET Core (.NET 9), Minimal API, MediatR-style handlers, EF Core, NodaTime
- **DB:** PostgreSQL (NodaTime dates — `LocalDate`, `LocalTime`)
- **AWS:** S3 (profile images bucket — presigned PUT upload)

### Step 5 — Frontend saves name + role + avatar into the auth store

**Auth store file:** [frontend/src/store/useAuthStore.ts:19-26](frontend/src/store/useAuthStore.ts#L19-L26)

```ts
export const useAuthStore = create<AuthState>((set) => ({
  isAuthenticated: false,
  user: null,
  setAuth: (user) => set({ isAuthenticated: true, user }),
  setAvatarUrl: (url) => set((state) => ({ user: state.user ? { ...state.user, avatarUrl: url } : null })),
  logout: () => set({ isAuthenticated: false, user: null }),
}));
```

**Zustand** is a tiny in-memory state store. Once `setAuth()` is called, every component in the app can read `user.role`, `user.firstName`, `user.avatarUrl` without hitting the backend again. It lives in the browser's JavaScript memory — if the user refreshes the page, it resets (see the page refresh note below).

Think of it like a whiteboard in the office — once you write the name and role there, anyone in the room can look at it without asking the front desk again.

### Bonus — What happens when the doctor refreshes the page

**File:** [frontend/src/routes/__root.tsx:8-30](frontend/src/routes/__root.tsx#L8-L30)

The auth store is in-memory — a page refresh wipes it. Before any page renders, `__root.tsx` runs a `beforeLoad` function:

| Line | What it does |
|------|-------------|
| 10 | `if (useAuthStore.getState().isAuthenticated) return` — if already logged in (normal navigation), skip |
| 12 | `const res = await getMe()` — calls the same `GET /api/v1/me` as in Step 3 |
| 20–26 | `setAuth(...)` — repopulates the auth store from the response |
| 27–29 | If the cookie expired → `getMe()` fails silently → protected routes redirect to `/login` |

This is why refreshing the page doesn't log you out — the cookie is still there and `getMe()` silently restores the session before the page finishes loading.

### 1.9 Real-Time Polling — Cards AND Table both update together // main feature

**What the user sees:** The stat card numbers and the table rows update automatically without any page refresh. If a receptionist checks a patient in on their screen, the doctor's dashboard reflects it within 1.5 seconds.

**File:** [frontend/src/features/dashboard/roles/UseDoctorSchedule.tsx:46-54](frontend/src/features/dashboard/roles/UseDoctorSchedule.tsx#L46-L54)

```ts
const { data, isLoading, isError } = useGetDoctorSchedule(
  {
    Date: getTodayStr(),
    Page: page,
    PageSize: PAGE_SIZE,
    Search: search.trim() || undefined,
  },
  { query: { refetchInterval: 1_500 } },   // ← polling: fires every 1.5 seconds
);
```

`refetchInterval: 1_500` tells TanStack Query to automatically re-send `GET /api/v1/doctors/schedule` every **1.5 seconds** in the background. No button click, no manual refresh — it just keeps running silently while the dashboard is open.

The important thing: **one API call returns everything.** The three stat card values and the table rows all come from the same `schedule` response object:

**File:** [frontend/src/features/dashboard/roles/DoctorDashboard.tsx:34-38](frontend/src/features/dashboard/roles/DoctorDashboard.tsx#L34-L38)

```ts
const totalCount   = Number(schedule?.totalCount ?? 0);                           // → "Today's Patients" card
const pendingCount = Number(schedule?.pendingCount ?? 0);                          // → "Pending Consultations" card
const nextTime     = formatLocalTime(schedule?.nextAppointmentTime ?? undefined);  // → "Next Appointment" card
// schedule.items → the table rows
```

So when polling fires and the backend returns new data, **all three cards and the table update at the same moment** from the same response. Think of it like a live scoreboard — every 1.5 seconds the screen re-reads the latest data from the server and repaints whatever changed.

```ts
function validateRxRow(row: PrescriptionRow): RxErrors {
  const errs: RxErrors = {};
  if (!isRowPartial(row)) return errs;        // skip blank rows entirely

  // Medication Name
  if (!row.medicationName.trim())
    errs.medicationName = "Medication name is required.";
  else if (row.medicationName.trim().length > 100)
    errs.medicationName = "Medication name must be 100 characters or fewer.";
  else if (!MED_NAME_RE.test(row.medicationName.trim()))
    errs.medicationName = "Medication name must contain letters and spaces only.";

  // Dosage — must include a number + unit
  if (!row.dosage.trim())
    errs.dosage = "Dosage is required.";
  else if (!DOSAGE_RE.test(row.dosage.trim()))
    errs.dosage = "Include a value and unit — e.g. 500mg, 5ml, 2 tablets.";

  // Frequency
  if (!row.frequency.trim())
    errs.frequency = "Frequency is required.";

  // Duration
  if (!row.durationDays)
    errs.durationDays = "Duration is required.";
  else {
    const days = Number(row.durationDays);
    if (!Number.isInteger(days) || days < 1)
      errs.durationDays = "Duration must be a whole number of at least 1 day.";
    else if (days > 365)
      errs.durationDays = "Duration cannot exceed 365 days.";
  }

  // Optional fields — only validate if filled
  if (row.takeWith.trim()) {
    if (!LETTERS_ONLY_RE.test(row.takeWith))  errs.takeWith = "Letters and spaces only.";
    else if (wordCount(row.takeWith) > 20)    errs.takeWith = "Must be 20 words or fewer.";
  }
  if (row.storage.trim()) {
    if (!/^\d+(\.\d+)?$/.test(row.storage.trim()))  errs.storage = "Storage must be a number (°C).";
    else if (parseFloat(row.storage) > 37)           errs.storage = "Temperature cannot exceed 37°C.";
  }
  if (row.missedDose.trim()) {
    if (!LETTERS_ONLY_RE.test(row.missedDose))    errs.missedDose = "Letters and spaces only.";
    else if (wordCount(row.missedDose) > 20)      errs.missedDose = "Must be 20 words or fewer.";
  }

  return errs;
}
```

### Step 5 — S3 Photo Upload: the 4-step flow // main feature

**File:** [frontend/src/features/profile/UseDoctorProfile.tsx:151-179](frontend/src/features/profile/UseDoctorProfile.tsx#L151-L179)

```ts
async function handleFileChange(e: React.ChangeEvent<HTMLInputElement>) {
  const file = e.target.files?.[0];
  if (!file) return;
  e.target.value = "";                           // line 154 — reset so same file can be re-picked

  setIsUploading(true);
  try {
    // ① get presigned URL from backend
    const { uploadUrl, publicUrl } = await fetchAvatarUploadUrl(file.type);

    // ② upload file DIRECTLY to S3 — backend never touches the file bytes
    const s3Res = await fetch(uploadUrl, { method: "PUT", body: file, headers: { "Content-Type": file.type } });
    if (!s3Res.ok) throw new Error("Upload to S3 failed");   // line 166

    // ③ tell backend to save the URL
    const cacheBustedUrl = `${publicUrl}?t=${Date.now()}`;   // line 168
    await patchAvatarUrl(cacheBustedUrl);

    // ④ update local state + auth store
    setMe((prev) => (prev ? { ...prev, avatarUrl: cacheBustedUrl } : prev));
    setAvatarUrl(cacheBustedUrl);                            // line 172 — updates sidebar
    toast.success("Profile photo updated");
  } catch {
    toast.error("Failed to upload photo. Please try again.");
  } finally {
    setIsUploading(false);
  }
}
```

| Step | What it does |
|------|-------------|
| ① `fetchAvatarUploadUrl(file.type)` — [line 78-87](frontend/src/features/profile/UseDoctorProfile.tsx#L78-L87) | `GET /api/v1/users/me/avatar/upload-url?contentType=image/jpeg` — backend returns `{ uploadUrl, publicUrl }` |
| ② `fetch(uploadUrl, { method: "PUT", body: file })` — line 160-164 | Uploads directly to AWS S3 — the file bytes never pass through the backend server |
| ③ `patchAvatarUrl(cacheBustedUrl)` — [line 89-97](frontend/src/features/profile/UseDoctorProfile.tsx#L89-L97) | `PATCH /api/v1/users/me/avatar` — tells the backend to save the S3 URL string to `Users.AvatarUrl` in PostgreSQL |
| ④ `setAvatarUrl(cacheBustedUrl)` — line 172 | Updates the **Zustand auth store** — the same store the sidebar reads. The sidebar avatar refreshes immediately without any page reload |

**Why `e.target.value = ""` at line 154?**
If the upload fails and the doctor tries to pick the same file again, the browser's `onChange` won't fire because the same file is already selected. Resetting to `""` clears it so the same file always triggers a new `onChange`.

**Why `?t=${Date.now()}` at line 168?**
The browser caches images by URL. Without the timestamp, the browser shows the old cached photo even though S3 has the new one. Appending a unique timestamp forces a re-fetch.

Think of the S3 upload like mailing a package: you ask the post office for a one-time shipping label (presigned URL), then drop the package directly at the carrier (S3) — the post office never sees the package contents.
